# C552 通信协议 V3.1

本文定义 STM32C552 传感器 Hub 与 H743 之间的双向串口协议，以及 C552 与 K230
之间的模式切换闭环。V3.1 为命令增加 `CMD_SEQ` 和执行回执；周期数据帧仍使用
`VERSION=0x03` 和 62 字节 V3 布局，不需要迁移传感器快照解析器。

## 1. 串口参数

| 参数 | 值 |
|---|---|
| 接口 | USART1，PA9 TX / PA10 RX |
| 波特率 | 460800 baud |
| 数据格式 | 8N1，无流控 |
| 编码 | 二进制，不附加 CR/LF |
| 上行周期 | 20 ms（50 Hz） |
| 上行帧长 | 62 字节，定长 |
| 下行帧长 | `LEN + 6` 字节，变长 |

USART1 为全双工：C552 周期发送上行快照的同时，也通过 DMA 环形缓冲区接收命令。

## 2. 字节序与 CRC

所有多字节整数均为大端。CRC 使用 CRC-16/CCITT-FALSE：

| 参数 | 值 |
|---|---|
| poly | `0x1021` |
| init | `0xFFFF` |
| refin / refout | false / false |
| xorout | `0x0000` |

上行帧 CRC 覆盖偏移 2～59，即 `VERSION + PAYLOAD_LEN + PAYLOAD`。下行命令 CRC
覆盖 `ID + LEN + PAYLOAD`。帧头和 CRC 字段本身不参与计算，CRC 高字节先发送。

## 3. C552 到上位机数据帧

### 3.1 完整结构

| 偏移 | 长度 | 字段 | 格式/说明 |
|---:|---:|---|---|
| 0 | 1 | HEADER_1 | 固定 `0xAA` |
| 1 | 1 | HEADER_2 | 固定 `0x55` |
| 2 | 1 | VERSION | 固定 `0x03` |
| 3 | 1 | PAYLOAD_LEN | 固定 `0x38`，表示 56 字节 payload |
| 4 | 1 | FRAME_SEQ | DMA 成功发送一帧后加 1，uint8 循环 |
| 5 | 1 | STATUS | TOF1/2、K230_1/2 的有效和过期状态 |
| 6 | 1 | TOF1_ID | 固定 `0x01` |
| 7 | 2 | TOF1_FILTERED_MM | uint16 |
| 9 | 2 | TOF1_MIN3_RAW_MM | uint16 |
| 11 | 2 | TOF1_SAMPLE_SEQ | uint16 |
| 13 | 2 | TOF1_SAMPLE_AGE_MS | uint16 |
| 15 | 1 | TOF2_ID | 固定 `0x02` |
| 16 | 2 | TOF2_FILTERED_MM | uint16 |
| 18 | 2 | TOF2_MIN3_RAW_MM | uint16 |
| 20 | 2 | TOF2_SAMPLE_SEQ | uint16 |
| 22 | 2 | TOF2_SAMPLE_AGE_MS | uint16 |
| 24 | 1 | K230_1_ID | 固定 `0x11` |
| 25 | 2 | K230_1_CENTER_X | int16，像素 |
| 27 | 2 | K230_1_CENTER_Y | int16，像素 |
| 29 | 2 | K230_1_X_ROTATION | uint16，值 / 100 度 |
| 31 | 2 | K230_1_Y_ROTATION | uint16，值 / 100 度 |
| 33 | 2 | K230_1_SAMPLE_SEQ | uint16 |
| 35 | 2 | K230_1_SAMPLE_AGE_MS | uint16 |
| 37 | 1 | K230_2_ID | 固定 `0x12` |
| 38 | 2 | K230_2_CENTER_X | int16，像素 |
| 40 | 2 | K230_2_CENTER_Y | int16，像素 |
| 42 | 2 | K230_2_X_ROTATION | uint16，值 / 100 度 |
| 44 | 2 | K230_2_Y_ROTATION | uint16，值 / 100 度 |
| 46 | 2 | K230_2_SAMPLE_SEQ | uint16 |
| 48 | 2 | K230_2_SAMPLE_AGE_MS | uint16 |
| 50 | 1 | TOF3_ID | 固定 `0x03` |
| 51 | 2 | TOF3_FILTERED_MM | uint16 |
| 53 | 2 | TOF3_MIN3_RAW_MM | uint16 |
| 55 | 2 | TOF3_SAMPLE_SEQ | uint16 |
| 57 | 2 | TOF3_SAMPLE_AGE_MS | uint16 |
| 59 | 1 | TOF3_FLAGS | bit0 VALID，bit1 STALE |
| 60 | 2 | CRC16 | CRC-16/CCITT-FALSE，大端 |

62 字节在 460800 baud、8N1 下理论发送时间约为 1.35 ms，20 ms 周期的线路占用率
约为 6.73%。

### 3.2 STATUS

| 位 | 定义 |
|---:|---|
| bit0 | TOF1_VALID |
| bit1 | TOF2_VALID |
| bit2 | K230_1_VALID |
| bit3 | K230_2_VALID |
| bit4 | TOF1_STALE |
| bit5 | TOF2_STALE |
| bit6 | K230_1_STALE |
| bit7 | K230_2_STALE |

V2 的 STATUS 定义保持不变。TOF3 使用偏移 59 的独立 `TOF3_FLAGS`：

| 位 | 定义 |
|---:|---|
| bit0 | TOF3_VALID |
| bit1 | TOF3_STALE |
| bit2～7 | 保留，当前为 0 |

| VALID | STALE | 含义 |
|---:|---:|---|
| 0 | 1 | 从未获得有效样本，或数据已过期 |
| 0 | 0 | 正在恢复，已收到样本但不足连续 3 个 |
| 1 | 0 | 当前数据可用于控制 |
| 1 | 1 | 非法组合，接收端应按无效处理 |

K230 无目标时不发送数据，超过 40 ms 后成为 `VALID=0, STALE=1`。这只表示当前无
可用目标，不应直接判定 K230 通信故障。

### 3.3 TOF 数据

- TOF1/TOF2 原始有效范围：0～1600 mm。
- TOF3 原始有效范围：0～2000 mm。
- `FILTERED_MM`：3 点中值后执行 EMA 的结果。
- `MIN3_RAW_MM`：最近 3 个有效原始值的最小值，仅作为近距离辅助通道。
- 从未形成结果时，两个距离字段均为 `0xFFFF`。
- 数据 stale 后允许保留最后结果用于诊断，但控制端必须以 VALID/STALE 为准。
- 每个 TOF 连续获得 3 个有效样本后置 VALID，过期时间为 500 ms。

### 3.4 K230 数据

- K230 识别到目标时发送结果，无目标时不发送。
- 坐标经过普通 3 点中值和 EMA，写入 int16 前四舍五入并饱和。
- 角度范围为 0～35999，对应 0.00～359.99 度。
- 角度滤波使用最短环形角差，允许跨越 0/360 度边界。
- 红色方块模式只提供中心坐标，两个角度为 0。
- 从未获得结果时，坐标和角度字段均为 0。

### 3.5 序号和年龄

- 每接收一个有效新传感器样本，对应 `SAMPLE_SEQ` 加 1；重复发送快照不会增加。
- `SAMPLE_AGE_MS` 是构建快照时距离最后有效样本的毫秒数，最大饱和为 65535。
- 从未收到有效样本时，`SAMPLE_AGE_MS=0xFFFF`。
- `FRAME_SEQ` 在构建和启动 DMA 时保持不变，只有 TX DMA 完成后才增加。
- DMA 启动失败或发送错误时保留当前 FRAME_SEQ，在后续 20 ms 节拍重试最新快照。

### 3.6 上位机接收要求

1. 在连续字节流中搜索 `AA 55`。
2. 检查 `VERSION=0x03`、`PAYLOAD_LEN=0x38`。
3. 等待完整 62 字节。
4. 检查固定设备 ID：`01 02 11 12 03`。
5. 校验偏移 2～59 的 CRC16。
6. CRC 通过后再检查 FRAME_SEQ、VALID、STALE、SAMPLE_SEQ 和 SAMPLE_AGE_MS。
7. 只有 `VALID=1, STALE=0` 的数据可以进入正常控制。
8. 接收器必须能从拆包、粘包、丢字节、杂字节和 CRC 错误中重新同步。

## 4. 上位机到 C552 命令帧

### 4.1 通用格式

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | HEADER | 固定 `AA 55` |
| 2 | 1 | ID | 命令目标 |
| 3 | 1 | LEN | PAYLOAD 长度 |
| 4 | LEN | PAYLOAD | 按 ID 和 CMD 解释 |
| 4+LEN | 2 | CRC16 | 校验 `ID + LEN + PAYLOAD`，大端 |

当前固件接收的最大 LEN 为 8。CRC 正确但内容非法的命令返回 `INVALID_COMMAND`；
无法解析帧头、长度或 CRC 的字节流不返回 ACK。

### 4.2 K230 模式切换

| 字段 | 值 |
|---|---|
| ID | `0x11`=K230_1，`0x12`=K230_2 |
| LEN | `0x03` |
| PAYLOAD[0] / CMD | `0x01`，设置识别模式 |
| PAYLOAD[1] / CMD_SEQ | H743 分配的 uint8 命令序号 |
| PAYLOAD[2] / MODE | `0x01`=AprilTag，`0x02`=红色方块 |

C552 验证命令后，先向 H743 返回 `ACCEPTED`，再按相同通用帧格式把 CMD_SEQ 转发
给目标 K230。K230 应用模式后返回 `APPLIED`。C552 每 100 ms 重试一次，包含首次
发送最多尝试 3 次；仍无匹配回执则向 H743 返回 `K230_TIMEOUT`。

| 操作 | 可直接发送的完整帧 |
|---|---|
| K230_1 / AprilTag，SEQ=2A | `AA 55 11 03 01 2A 01 EA E7` |
| K230_1 / 红色方块，SEQ=2A | `AA 55 11 03 01 2A 02 DA 84` |
| K230_2 / AprilTag，SEQ=2A | `AA 55 12 03 01 2A 01 04 35` |
| K230_2 / 红色方块，SEQ=2A | `AA 55 12 03 01 2A 02 34 56` |

### 4.3 机械爪控制

| 字段 | 值 |
|---|---|
| ID | 固定 `0x20` |
| LEN | 固定 `0x04` |
| PAYLOAD[0] / CMD | 固定 `0x02`，设置开合状态 |
| PAYLOAD[1] / CMD_SEQ | H743 分配的 uint8 命令序号 |
| PAYLOAD[2] / CHANNEL | `0`=两路，`1`=PWM1，`2`=PWM2 |
| PAYLOAD[3] / STATE | `0`=打开，`1`=闭合 |

| 通道 | 定时器/引脚 | 周期 | 打开 | 闭合 |
|---|---|---:|---:|---:|
| PWM1 | TIM1_CH1 / PA8 | 20 ms | 1000 us | 2000 us |
| PWM2 | TIM2_CH1 / PA0 | 20 ms | 1000 us | 2000 us |

| 操作 | 可直接发送的完整帧 |
|---|---|
| 两路打开，SEQ=2A | `AA 55 20 04 02 2A 00 00 1E 71` |
| 两路闭合，SEQ=2A | `AA 55 20 04 02 2A 00 01 0E 50` |

单路控制只需把 CHANNEL 改成 1 或 2 并重新计算 CRC。实际舵机方向和安全脉宽必须
上板标定；可修改 `sensor_hub.c` 中的 `SERVO_OPEN_PULSE_US` 和
`SERVO_CLOSED_PULSE_US`，无需修改协议。

### 4.4 命令回执

H743 与 K230 使用相同的回执 payload：

| 字段 | 值 |
|---|---|
| ID | 原命令目标 ID |
| LEN | 固定 `0x05` |
| PAYLOAD[0] / ACK | 固定 `0x80` |
| PAYLOAD[1] / CMD | 被确认的命令 |
| PAYLOAD[2] / CMD_SEQ | 原命令序号 |
| PAYLOAD[3] / RESULT | 执行阶段或结果 |
| PAYLOAD[4] / VALUE | 模式/状态；错误时可携带诊断值 |

| RESULT | 名称 | 含义 |
|---:|---|---|
| `0x00` | APPLIED | 目标设备已经应用命令 |
| `0x01` | ACCEPTED | C552 已接受，正在等待 K230 |
| `0x02` | INVALID_COMMAND | 命令或参数非法 |
| `0x03` | FORWARD_FAILED | C552 向 K230 发送失败 |
| `0x04` | K230_TIMEOUT | 3 次发送后仍未收到匹配回执 |
| `0x05` | K230_REJECTED | K230 拒绝或返回非成功结果 |
| `0x06` | SEQUENCE_MISMATCH | 收到的 K230 回执序号不匹配 |
| `0x07` | BUSY | 该 K230 已有一条命令等待确认 |

示例（K230_1、CMD_SEQ=`0x2A`、红色方块）：

| 阶段 | 完整帧 |
|---|---|
| C552 已受理 | `AA 55 11 05 80 01 2A 01 02 3B C5` |
| K230 已应用，C552 最终确认 | `AA 55 11 05 80 01 2A 00 02 08 F4` |
| K230 超时 | `AA 55 11 05 80 01 2A 04 02 C4 30` |
| 机械爪已闭合 | `AA 55 20 05 80 02 2A 00 01 42 A7` |

H743 只有收到匹配 `ID + CMD + CMD_SEQ` 且 `RESULT=APPLIED` 的最终回执，才能认为
命令已经执行。`ACCEPTED` 不能作为 K230 已切换模式的依据。


## 6. 版本迁移

- 接收端将期望版本从 `0x02` 改为 `0x03`。
- 将 PAYLOAD_LEN 从 `0x2E` 改为 `0x38`，总帧长从 52 改为 62。
- V2 偏移 4～49 的字段不变。
- 在偏移 50～59 解析 TOF3 数据和 flags。
- CRC 从偏移 50～51 移至 60～61，校验范围从 2～49 改为 2～59。
- V3.0 到 V3.1：周期帧不变；所有命令增加 CMD_SEQ，并解析 `ACK=0x80` 回执。
