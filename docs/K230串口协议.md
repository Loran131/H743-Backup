# K230 串口二进制协议 V3.1

## 模式切换命令

模式切换沿用通用帧。`ID` 是目标 K230 的 ID，`LEN` 固定为 `0x03`。

| PAYLOAD 偏移 | 长度 | 字段 | 定义 |
|---:|---:|---|---|
| 0 | 1 | CMD | 固定 `0x01`，表示设置识别模式 |
| 1 | 1 | CMD_SEQ | C552 转发的 uint8 命令序号 |
| 2 | 1 | MODE | `0x01`=AprilTag，`0x02`=红色物块 |

发送端可直接调用：

```python
from k230_protocol import K230_1_ID, MODE_RED_BLOCK, pack_mode_command

# 返回值已经包含帧头和 CRC，可直接写串口。
uart.write(pack_mode_command(K230_1_ID, MODE_RED_BLOCK))
```

K230 收到有效命令后切换模式，只有切换完成后才返回 APPLIED 回执。两种模式的识别
结果都使用下述 16 字节 K230 数据帧；红色物块模式填写中心像素坐标，`Degree_X`
和 `Degree_Y` 均为 0。

## 模式切换回执

回执 `LEN=0x05`，PAYLOAD 为：

| 偏移 | 长度 | 字段 | 定义 |
|---:|---:|---|---|
| 0 | 1 | ACK | 固定 `0x80` |
| 1 | 1 | CMD | 固定 `0x01` |
| 2 | 1 | CMD_SEQ | 原命令序号 |
| 3 | 1 | RESULT | `0x00`=APPLIED，其他值表示失败 |
| 4 | 1 | MODE | 已实际应用的模式 |

例如 K230_1 已应用 CMD_SEQ=`0x2A` 的红色方块模式后返回：

```text
AA 55 11 05 80 01 2A 00 02 08 F4
```

收到相同 CMD_SEQ 和 MODE 的重试命令时，K230 应保持幂等：若该模式已经应用，直接
再次返回 APPLIED，不应重复执行有副作用的初始化流程。

串口参数为 115200 baud、8 数据位、无校验、1 停止位。二进制帧不附加 `\r\n`。

## 通用帧结构

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | 帧头 | 固定 `0xAA 0x55` |
| 2 | 1 | ID | TOF=`0x01`，K230_1=`0x11`，K230_2=`0x12` |
| 3 | 1 | LEN | PAYLOAD 字节数，不含帧头、ID、LEN 和 CRC |
| 4 | LEN | PAYLOAD | 按 ID 解释 |
| 4+LEN | 2 | CRC16 | CRC-16/CCITT-FALSE，大端 |

CRC 参数：`poly=0x1021`、`init=0xFFFF`、`refin=false`、`refout=false`、`xorout=0x0000`。校验范围从 ID 开始，到 PAYLOAD 最后一个字节结束，即 `ID + LEN + PAYLOAD`。

## K230 数据帧

K230 的 `LEN` 固定为 `0x10`，完整帧固定为 22 字节。所有多字节整数均为大端有符号 `int32`。

| PAYLOAD 偏移 | 长度 | 字段 | 换算 |
|---:|---:|---|---|
| 0 | 4 | Center_X | 接收值，像素 |
| 4 | 4 | Center_Y | 接收值，像素 |
| 8 | 4 | Degree_X | 接收值 / 100.0，单位为度 |
| 12 | 4 | Degree_Y | 接收值 / 100.0，单位为度 |

例如 K230_1 发送 `center=(-120, 300), degree=(12.34, -5.67)` 时，完整帧为：

```text
AA 55 11 10 FF FF FF 88 00 00 01 2C 00 00 04 D2 FF FF FD C9 90 51
```

发送端调用：

```python
uart.write(pack_k230_frame(0x11, center_x, center_y, degree_x, degree_y))
```

## 接收解析

串口是字节流，一次 `read()` 不一定是一帧，也可能同时包含多帧。应把每次收到的数据交给同一个 `FrameParser` 实例：

```python
from k230_protocol import FrameParser, decode_k230_payload

parser = FrameParser()

data = uart.read()
for device_id, payload in parser.feed(data):
    if device_id in (0x11, 0x12):
        result = decode_k230_payload(device_id, payload)
        print(result)
    elif device_id == 0x01:
        # 按 TOF 的 PAYLOAD 定义解析
        pass
```

解析器依次搜索帧头、读取长度、等待完整帧、验证 CRC；长度非法或 CRC 错误时会重新搜索帧头，因此可以处理拆包、粘包、前导杂字节和损坏帧。STM32 端应采用相同状态机，并避免使用单字节接收标志保存连续 UART 数据，建议在接收中断中写入环形缓冲区，再在主循环中逐字节解析。
