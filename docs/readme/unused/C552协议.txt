C552 Sensor Hub -> H743 串口协议 V1.0

1. 串口参数

波特率：460800 baud
数据位：8 bit
停止位：1 bit
校验位：无
流控：无
发送方向：C552 -> H743
建议发送频率：200 Hz（每 5 ms 一帧）

本协议为二进制定长帧，不附加 CR/LF。每帧固定 30 字节。


2. 完整帧结构

字节偏移  字段              长度  格式/说明
0         帧头1             1     固定 0xAA
1         帧头2             1     固定 0x55
2         数据区长度        1     固定 0x19（25 字节，对应偏移 4~28）
3         帧序列号          1     0~255 循环递增
4         TOF1 ID           1     固定 0x01
5~6       TOF1 距离         2     uint16，大端，单位 mm
7         TOF2 ID           1     固定 0x02
8~9       TOF2 距离         2     uint16，大端，单位 mm
10        K230_1 ID         1     固定 0x11
11~12     K230_1 Center_X   2     int16，大端，单位像素
13~14     K230_1 Center_Y   2     int16，大端，单位像素
15~16     K230_1 Degree_X   2     int16，大端，实际角度 = 接收值 / 100.0 度
17~18     K230_1 Degree_Y   2     int16，大端，实际角度 = 接收值 / 100.0 度
19        K230_2 ID         1     固定 0x12
20~21     K230_2 Center_X   2     int16，大端，单位像素
22~23     K230_2 Center_Y   2     int16，大端，单位像素
24~25     K230_2 Degree_X   2     int16，大端，实际角度 = 接收值 / 100.0 度
26~27     K230_2 Degree_Y   2     int16，大端，实际角度 = 接收值 / 100.0 度
28        设备状态 STATUS   1     各逻辑设备的有效和过期状态，定义见第 4 节
29        XOR 校验          1     对偏移 2~28 的全部字节逐字节异或

总长度计算：

2 字节帧头 + 1 字节长度 + 1 字节序列号 + 25 字节数据区 + 1 字节校验 = 30 字节


3. 逻辑设备 ID

帧内 ID 表示逻辑设备身份，不表示设备连接在哪一个物理串口：

0x01：TOF1
0x02：TOF2
0x11：K230_1
0x12：K230_2

C552 根据传感器原始帧中的设备 ID 判断逻辑身份。即使传感器交换串口连接，输出帧中的字段位置和逻辑 ID 也保持不变。

若检测到未知 ID、重复 ID 或 ID 冲突，对应逻辑设备必须标记为无效，不得根据物理串口位置猜测身份。


4. STATUS 定义

bit0：TOF1_VALID
bit1：TOF2_VALID
bit2：K230_1_VALID
bit3：K230_2_VALID
bit4：TOF1_STALE
bit5：TOF2_STALE
bit6：K230_1_STALE
bit7：K230_2_STALE

VALID 位定义：

1：设备 ID 已确认，并且至少成功接收过一帧校验正确、字段合法的数据。
0：设备尚未识别、从未收到有效数据、ID 冲突或当前数据不可用。

STALE 位定义：

1：设备数据已超过 C552 规定的更新时间，当前数值不是新鲜数据。
0：最近一次有效数据仍在规定的更新时间内。

设备从未产生有效数据时，建议使用 VALID=0、STALE=1。
设备短暂断线时可以保留最后一次有效数值，但必须设置 STALE=1。
H743 必须以 STATUS 为准，不能仅根据数值判断设备是否有效。


5. 数据编码规则

所有多字节整数均使用大端模式，高字节在前。

uint16 编码：

value = (frame[high_offset] << 8) | frame[low_offset]

int16 编码：

先按 uint16 组合，再解释为二进制补码 int16。

TOF 距离正常范围为 0~8191 mm。无有效距离且没有历史数据时填 0xFFFF，同时清除对应 VALID 位。

K230 原始协议使用 int32。写入本协议的 int16 字段前，C552 必须进行饱和处理：

大于 32767 时发送 32767；
小于 -32768 时发送 -32768；
禁止直接截断低 16 位后发送。

当 K230 数据无效且没有历史数据时，对应四个字段填 0，状态由 STATUS 表示。


6. 帧序列号

帧序列号每发送一帧加 1，达到 255 后回到 0。

H743 可通过相邻有效帧序列号判断丢帧：

expected_seq = (last_seq + 1) & 0xFF

序列号只表示 C552 输出帧顺序，不等同于任一传感器的采样序号。


7. XOR 校验

校验初始值为 0x00，对偏移 2~28 的 27 个字节依次执行异或：

checksum = frame[2] XOR frame[3] XOR ... XOR frame[28]

计算结果写入偏移 29。

帧头 0xAA 0x55 和校验字节本身不参与计算。


8. H743 接收与重新同步

H743 应将串口数据作为连续字节流处理，不能假设一次 DMA 或一次中断刚好收到一帧。

推荐解析流程：

1）搜索连续帧头 0xAA 0x55；
2）检查 LEN 是否为 0x19；
3）等待累计收到完整 30 字节；
4）检查固定逻辑 ID 是否分别为 0x01、0x02、0x11、0x12；
5）验证偏移 29 的 XOR 校验；
6）校验成功后更新数据，否则丢弃当前候选帧并重新搜索帧头。

解析器必须能够处理拆包、粘包、前导杂字节、丢字节和校验错误。


9. 发送时序要求

C552 建议以固定 200 Hz 周期发送聚合帧，每帧使用发送时刻各逻辑设备的最新数据快照。

在 460800 baud、8N1 下，每个字节占 10 bit，30 字节帧的理论线速时间约为：

30 * 10 / 460800 = 0.651 ms

C552 应使用 UART TX DMA 发送，禁止在传感器接收中断中阻塞等待整帧发送完成。

构造一帧期间应保证数据快照一致，不能出现同一逻辑设备的部分字段来自旧数据、部分字段来自新数据。
