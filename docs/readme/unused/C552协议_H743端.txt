C552 Sensor Hub -> H743 接收与解析设计建议 V1.0


1. 目标

H743通过USART3接收C552发送的传感器聚合帧。

当前阶段重点完成：

1）稳定接收连续串口数据；
2）正确处理拆包、粘包、杂字节、丢字节和错误帧；
3）解析并发布完整、可信的数据快照；
4）提供通信和设备状态，供后续运动控制使用；
5）通信故障时停止运动，但接收和解析必须持续运行，直到通信恢复。


2. 协议固定参数

串口：USART3
波特率：460800 baud
格式：8N1
流控：无
方向：C552 -> H743
发送频率：约200 Hz，每5 ms一帧
帧长度：固定30字节
帧头：0xAA 0x55
数据区长度字段：0x19
校验：frame[2]到frame[28]逐字节XOR，结果位于frame[29]

在460800 baud、8N1下：

单字节线速时间约为21.7 us；
单帧30字节发送时间约为0.651 ms；
200 Hz发送时，相邻帧之间通常约有4.35 ms空闲时间。


3. 完整帧格式

偏移    字段                    长度    说明
0       帧头1                   1       固定0xAA
1       帧头2                   1       固定0x55
2       数据区长度              1       固定0x19
3       帧序列号                1       0~255循环递增
4       TOF1 ID                 1       固定0x01
5~6     TOF1距离                2       uint16，大端，单位mm
7       TOF2 ID                 1       固定0x02
8~9     TOF2距离                2       uint16，大端，单位mm
10      K230_1 ID               1       固定0x11
11~12   K230_1 Center_X         2       int16，大端，单位像素
13~14   K230_1 Center_Y         2       int16，大端，单位像素
15~16   K230_1 Degree_X         2       int16，大端，单位0.01度
17~18   K230_1 Degree_Y         2       int16，大端，单位0.01度
19      K230_2 ID               1       固定0x12
20~21   K230_2 Center_X         2       int16，大端，单位像素
22~23   K230_2 Center_Y         2       int16，大端，单位像素
24~25   K230_2 Degree_X         2       int16，大端，单位0.01度
26~27   K230_2 Degree_Y         2       int16，大端，单位0.01度
28      STATUS                  1       设备有效和过期状态
29      XOR校验                 1       frame[2] XOR ... XOR frame[28]

禁止直接把接收缓冲区强制转换成C结构体。协议数据为大端，H743为小端，
并且C结构体可能存在填充和对齐。所有多字节字段应通过大端读取函数显式解析。

角度建议在接收层保留int16原始值，单位为0.01度。接收中断中不进行浮点运算，
需要使用角度时再转换为degree_raw / 100.0f。


4. STATUS解释和使用原则

bit0：TOF1_VALID
bit1：TOF2_VALID
bit2：K230_1_VALID
bit3：K230_2_VALID
bit4：TOF1_STALE
bit5：TOF2_STALE
bit6：K230_1_STALE
bit7：K230_2_STALE

H743必须优先判断对应设备的VALID位，然后才能读取和使用其数值字段。

规则如下：

1）VALID=0：对应数值字段没有业务意义，不得用于运动控制；
2）VALID=1：对应数值字段有意义，包括数值为0的情况；
3）例如TOF距离为0 mm且VALID=1时，0 mm是有效测量值，不能当成无效数据；
4）VALID=1且STALE=1：数值可能是C552保留的历史值，可用于显示和诊断，
   但不得用于实时运动控制；
5）VALID=0且STALE=0：仍然按无效处理，VALID优先级最高；
6）不得通过0、0xFFFF或其他特殊数值代替STATUS进行有效性判断。

建议统一定义设备可用条件：

device_usable = link_online && valid && !stale && data_plausible

不同运动模式可以配置required_sensor_mask。当前运动所依赖的任一设备不可用时，
应停止或取消当前运动。


5. USART3 DMA接收建议

推荐配置USART3 RX DMA循环接收：

方向：Peripheral to Memory
外设数据宽度：Byte
内存数据宽度：Byte
内存地址递增：Enable
DMA模式：Circular
优先级：High
缓冲区大小：建议256或512字节
HAL接口：HAL_UARTEx_ReceiveToIdle_DMA()

必须将串口输入视为连续字节流，不能假设：

1）一次DMA回调恰好对应一帧；
2）一次回调一定收到30字节；
3）帧头一定出现在DMA缓冲区起始位置；
4）两个回调之间一定只有一帧。

HAL_UARTEx_RxEventCallback()中的Size表示DMA缓冲区当前写入位置，
不是本次新增字节数量。应保存上一次处理位置，根据新旧位置计算一个或两个新增区间，
并且只把新增字节送入协议解析器，避免重复解析或遗漏回绕区域。

DMA/UART回调中只执行以下轻量工作：

1）取得DMA新增数据区间；
2）把新增字节送入解析器；
3）更新接收位置和必要计数；
4）合法帧完成后发布数据快照。

中断和DMA回调中禁止执行printf、阻塞等待、浮点计算或运动控制。


6. H743 DMA内存注意事项

常规DMA1/DMA2不能访问0x20000000区域的DTCM，因此DMA接收缓冲区不能放在DTCM。

推荐使用：

AXI SRAM：0x24000000区域；
或D2 SRAM：0x30000000区域。

如果以后启用D-Cache，DMA接收缓冲区应配置为MPU非缓存区域；或者严格按照
32字节Cache Line要求进行地址和长度对齐，并在CPU读取DMA写入的数据前执行Cache失效。
对于持续循环接收，独立的非缓存DMA区域通常更容易保证正确性。


7. 连续字节流解析流程

推荐使用滑动窗口或等价的流式状态机：

1）在连续字节流中搜索0xAA 0x55；
2）找到帧头后检查frame[2]是否为0x19；
3）不足30字节时保留当前候选数据，等待后续字节；
4）累计到30字节后检查固定ID：
   frame[4]  == 0x01；
   frame[7]  == 0x02；
   frame[10] == 0x11；
   frame[19] == 0x12；
5）计算frame[2]到frame[28]的XOR，并与frame[29]比较；
6）全部检查通过后解析到临时数据结构；
7）临时结构完全解析完成后，一次性发布新快照；
8）合法帧消费30字节，然后继续搜索下一帧；
9）候选帧检查失败时只滑过候选帧的第一个字节，然后重新搜索帧头。

错误候选帧不能直接丢弃整个30字节，因为真实帧头可能位于候选帧内部。
只滑过一个字节可以在前导杂字节、伪帧头、丢字节和粘包情况下尽快重新同步。


8. 帧合法性和数据发布

只有同时满足以下条件，当前帧才是合法通信帧：

1）帧头正确；
2）长度字段正确；
3）四个固定逻辑ID正确；
4）XOR校验正确。

任何检查失败都不能更新业务数据，也不能更新时间戳last_valid_frame_tick。
应只增加相应错误计数，然后继续接收和重新同步。

禁止在解析过程中逐字段修改供运动控制使用的全局数据。应先解析到局部临时结构，
全部验证完成后再原子发布。主循环读取多字段快照时，应使用短临界区、双缓冲或其他
一致性机制，防止读到一半来自旧帧、一半来自新帧的数据。

建议解析后的快照至少包含：

seq
status
tof1_mm
tof2_mm
k230_1_center_x
k230_1_center_y
k230_1_degree_x_cdeg
k230_1_degree_y_cdeg
k230_2_center_x
k230_2_center_y
k230_2_degree_x_cdeg
k230_2_degree_y_cdeg
rx_tick


9. H743本地链路超时

H743必须维护自己的通信新鲜度，不能只依赖最近一帧中的STATUS。
如果C552断电或通信线断开，最后一帧的STATUS可能永久停留在VALID=1、STALE=0。

建议维护：

last_valid_frame_tick
link_online
link_timeout_warning

只有完整合法帧才能更新last_valid_frame_tick。超时判断应使用可处理系统Tick回绕的写法：

(uint32_t)(now - last_valid_frame_tick) > timeout_ms

超时阈值可根据最终控制要求设置在20~50 ms范围。

超过阈值未收到合法帧时：

1）设置link_timeout_warning；
2）设置link_online=false；
3）立即停止或取消当前运动；
4）保留最后一帧仅供显示和故障诊断；
5）禁止最后一帧继续参与运动控制；
6）USART3 DMA接收和协议解析必须继续运行；
7）直到重新收到合法帧后再进入恢复判断。

通信恢复后不应自动续跑故障前被中断的运动。通信状态可以恢复正常，但旧运动任务应保持
取消，由上层重新检查所有条件并下发新的运动命令。


10. 故障触发和恢复防抖

建议采用故障快速触发、恢复适当防抖的策略：

1）链路达到超时阈值后立即停止运动；
2）当前合法帧中，必需设备VALID=0或STALE=1时，立即禁止依赖该设备的运动；
3）通信恢复时，连续收到3~5帧合法帧后再清除链路警示；
4）设备恢复时，对应设备连续若干帧VALID=1且STALE=0后，才允许启动新运动；
5）恢复防抖只能延迟重新允许运动，不能延迟故障停止。


11. 序列号处理

序列号只用于监测C552输出帧的连续性，不参与传感器数值解释。

建议处理规则：

1）收到第一帧合法帧时建立序列号基准；
2）expected_seq = (last_seq + 1) & 0xFF；
3）当前序列号等于expected_seq时正常；
4）序列号跳跃时累计估算丢帧数；
5）序列号相同时记录重复帧；
6）当前帧只要其他校验正确，序列号异常不应导致该帧被拒绝；
7）链路超时、C552重启或重新连接后，允许重新建立序列号基准。

可以统计固定时间窗口内的丢帧比例。丢帧率持续过高时设置通信质量警示，
但应与完全断线的link_timeout_warning区分。


12. UART和DMA错误恢复

建议分别统计以下错误：

UART ORE：接收溢出；
UART FE：帧格式错误，可能来自波特率不匹配或线路问题；
UART NE：噪声错误；
UART PE：校验错误，虽然当前配置无校验，仍可保留统一诊断；
DMA缓冲区覆盖；
DMA启动或重启失败。

发生UART或DMA错误时：

1）记录错误类型和次数；
2）清除对应硬件错误状态；
3）必要时中止并重新启动USART3 RX DMA；
4）重置协议候选帧状态，重新搜索帧头；
5）不得因一次错误永久停止接收；
6）连续恢复失败时保持运动禁止，并设置严重通信故障标志。


13. 数值合理性检查

STATUS通过后，可以进行独立的应用层合理性检查，但不能改变协议VALID的定义。

例如：

1）TOF在VALID=1时应处于协议规定的0~8191 mm范围；
2）K230坐标和角度是否超出机械系统允许范围；
3）相邻帧变化速度是否超出系统物理能力；
4）多个传感器之间是否存在明显矛盾。

合理性检查失败时，建议设置独立的DATA_IMPLAUSIBLE标志并禁止相关运动。
不要把合法的0值当作错误，也不要静默限幅后继续控制。原始接收值应保留用于诊断。

15. 与现有H743工程的关系

当前工程USART3仍配置为115200，需要改为460800。

当前USART3采用每次1字节的中断接收，并在主循环中重新启动下一次接收。
这种方式在460800 baud下存在明显丢字节风险，应替换为DMA连续接收。

当前tof.c也直接使用huart3进行阻塞收发。C552作为传感器聚合端接入USART3后，
这些直接TOF通信函数不能再与C552接收同时使用。应确保它们不被调用，或将其迁移到
其他独立串口。

H743只收不发。


16. 建议测试项目

解析器至少应覆盖以下测试：

1）完整合法帧一次送入；
2）合法帧逐字节送入；
3）合法帧在任意位置拆成多个数据块；
4）两帧或多帧连续粘包；
5）帧前存在任意杂字节；
6）0xAA与0x55跨DMA缓冲区边界；
7）错误长度后紧跟合法帧；
8）错误固定ID后紧跟合法帧；
9）错误XOR后紧跟合法帧；
10）中间丢失一个字节后重新同步；
11）候选帧内部包含0xAA 0x55；
12）序列号255回绕到0；
13）C552断开、超时、重新连接；
14）VALID=1且数值为0；
15）VALID=0但数值看起来正常；
16）VALID=1且STALE=1；
17）UART错误后DMA接收恢复；
18）DMA缓冲区发生回绕。


17. 总体实现原则

USART3和DMA只负责稳定接收连续字节；
协议解析器负责帧同步、固定字段检查、XOR校验和大端解码；
数据发布层负责提供一致的合法帧快照；
状态管理层负责STATUS、链路超时、错误统计和恢复防抖；
运动控制只能使用link_online且对应VALID=1、STALE=0、数据合理的快照。

任何通信故障都不能停止USART3 DMA接收和协议解析本身。运动停止后，接收器必须继续工作，
以便识别C552重新连接和通信恢复。

V1.0继续使用现有XOR校验。如果后续该链路承担更高安全等级的运动控制，建议协议V2升级为
CRC-16，并保留序列号、STATUS和H743本地链路超时机制。
