## 2. 信息可信度顺序

遇到配置冲突时，按以下顺序判断当前真实状态：

1. `Core/Src`、`Core/Inc` 中实际参与编译的源码；
2. `MDK-ARM/100.uvprojx` 中的文件列表和编译配置；
3. `MDK-ARM/100/100.map` 中的最终链接结果；
4. `100.ioc`；

当前 `100.ioc` 仍有历史配置，例如 FDCAN1 和 SPI2 引脚配置，而运行源码使用 FDCAN2。

## 3. 系统数据流

```text
USART1/USB-TTL
    -> usart.c 命令行接收
    -> shell.c 命令分发
    -> smd.c PD42S1协议
    -> fdcan.c FDCAN2传输
    -> 电机驱动器

Z-axis controller
    -> UART4 115200 8N1
    -> PA12 TX / PA11 RX
    -> DRV8711控制MCU

C552 Sensor Hub
    -> USART3 460800
    -> DMA1 Stream0循环缓冲区
    -> usart.c提取DMA新增字节
    -> c552.c连续流同步、校验、解码
    -> C552数据快照和健康状态
    -> shell命令C552显示
    -> 后续PID/运动控制模块读取并执行模式相关安全联锁

I2C2
    -> eeprom.c
    -> M24C02 EEPROM

```

## 4. 启动流程

`Core/Src/main.c` 当前按以下顺序启动：

1. 配置 MPU、HAL 和 480 MHz 系统时钟；
2. 初始化 GPIO；
3. 初始化 UART4、UART5、USART1、USART3；
4. 紧接 USART3 初始化后启动 C552 解析器和 RX DMA，避免上电数据造成 ORE；
5. 初始化 USART6、FDCAN2、I2C2、QSPI；
6. 初始化 LED 和按键；
7. 探测 EEPROM；
8. 启动 USART1 Shell；
9. 启动约 1 秒超时的 IWDG；
10. 进入主循环。

主循环持续执行：

- 喂狗；
- 每 10 ms 扫描按键；
- 尝试恢复 USART3 DMA，并检查 C552 链路超时；
- 检查 CAN 拼帧超时和 CAN 故障恢复；
- 处理异步 CAN 电机回复；
- 轮询 USART1 Shell；
- 翻转 LED0 作为心跳。

| `Core/Src/c552.c` | 字节流解析、重新同步、校验、解码、健康状态和统计 | 候选帧失败时滑动重同步；合法帧才发布快照 |

| `Core/Src/usart.c` | USART3底层DMA接收和HAL回调 | DMA1 Stream0循环模式，512字节、32字节对齐缓冲区 |
| `Core/Inc/usart.h` | UART句柄、DMA句柄和接收接口 | `USART3_StartRx()`、`USART3_RxPoll()` |

C552当前固定策略：

- USART3：460800 8N1；
- DMA缓冲区实际链接在AXI SRAM `0x24000000`区域，不在DTCM；
- 链路超时：50 ms；
- 链路和设备恢复：连续3帧；
- 默认只要求TOF1、TOF2可用；K230无目标仅产生警示，不触发全局急停；
- 设备可用条件：链路在线、`VALID=1`、`STALE=0`且数值合理；
- `VALID=0`时数值字段不得使用；
- `VALID=1`时数值0是合法数据；
- UART/DMA错误后先在回调中重启，失败后由主循环每10 ms继续重试；
- 超时和设备可用性由C552模块持续发布；后续PID/运动控制模块必须据此执行模式相关停机；
- 通信恢复不会自动续跑故障前的运动。

Shell输入大写命令 `C552`，USART1将输出：

- 链路 ONLINE、RECOVERING 或 TIMEOUT；
- 总警示和运动许可；
- 序列号、STATUS和帧龄；
- 四个设备的 VALID、STALE、READY和解析值；
- 版本、长度、ID、CRC、序列号、UART和DMA错误计数。

中断和DMA回调中禁止使用 `printf`、阻塞等待、浮点计算或运动控制。

## 10. 重要约束和已知风险

1. 不要直接重新生成CubeMX代码。先比较`100.ioc`和当前源码，尤其是FDCAN、SPI2、DMA和中断。
2. 当前CAN是FDCAN2 PB12/PB13，不是历史文档中的FDCAN1 PA11/PA12。
3. UART4已由`main.c`初始化为Z轴控制链路，占用PA11/PA12；`100.ioc`仍把这两个引脚标为历史FDCAN1，禁止直接重新生成覆盖源码。
4. Ethernet当前禁用。没有RMII 50 MHz参考时钟时调用完整HAL ETH初始化会进入Error_Handler。
5. USART3由C552 DMA独占，不允许再用阻塞式TOF收发。
6. DMA1/2不能访问DTCM `0x20000000`。C552 DMA缓冲区当前位于AXI SRAM。
7. 当前未启用D-Cache；以后启用时必须处理DMA Cache一致性或划分非缓存区。
8. IWDG约1秒超时。长时间阻塞、调试断点或新增阻塞等待可能导致复位。
9. `axis.c`、`servo.c`、`stepper.c`仅保留为历史源码，未加入Keil编译，不能作为当前运行路径。
10. 新PID/运动控制模块必须接管运动状态、C552安全联锁和电机停止；当前main循环只维护通信，不会自动停止活动电机。
11. `wdg.c`与`iwdg.c`是两套IWDG封装，只能选择一套初始化。
12. C552默认只把两个TOF视为运动必需设备；视觉相关运动仍需在业务层单独检查对应K230是否可用。
13. `printf`走USART1轮询发送，长日志会阻塞主循环；中断中绝对不能打印。
14. 当前目录没有Git保护。修改前后应明确列出触碰的文件，并避免覆盖历史文件。
