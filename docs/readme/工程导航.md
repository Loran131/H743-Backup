## 3. 系统数据流

```text
USART1/USB-TTL
    -> usart.c 命令行接收
    -> shell.c 命令分发
    -> smd.c PD42S1协议
    -> fdcan.c FDCAN2传输
    -> 电机驱动器

Z-axis controller
    -> USART6 9600 8N1
    -> PC6 TX / PC7 RX
    -> DRV8711控制MCU

C552 Sensor Hub
    -> USART3 460800
    -> DMA1 Stream0循环缓冲区
    -> usart.c提取DMA新增字节
    -> c552.c连续流同步、校验、解码
    -> C552数据快照和健康状态
    -> shell命令C552显示
    -> 后续PID/运动控制模块读取并执行模式相关安全联锁

I2C2
    -> eeprom.c
    -> M24C02 EEPROM

```

## 4. 启动流程

`Core/Src/main.c` 当前按以下顺序启动：

1. 配置 MPU、HAL 和 480 MHz 系统时钟；
2. 初始化 GPIO；
3. 初始化 USART3、USART1、USART6、FDCAN2、I2C2、QSPI；
4. 初始化 Z 轴协议并启动 USART6 RX DMA；
5. 初始化 C552 解析器并启动 USART3 RX DMA；
6. 初始化 LED、SysTick 并探测 EEPROM；
7. 初始化 FreeRTOS 对象和运动模块；
8. 创建 DefaultTask、SocketTask、LegacyIoTask、ShellTask 和 MonitorTask；
9. 启动调度器，之后不再使用 `main.c` 中的历史轮询循环。

运行期职责：LegacyIoTask 轮询 C552、CAN、X/Y/Z、标定、对正、P6/P7 状态机和事件；
ShellTask 处理 USART1 命令；MonitorTask 检查三个关键任务心跳，健康后启动约 2 秒 IWDG并持续喂狗；
DefaultTask 初始化 LwIP，SocketTask 服务 TCP 5000。

C552当前固定策略：

- USART3：460800 8N1；
- DMA缓冲区实际链接在AXI SRAM `0x24000000`区域，不在DTCM；
- 链路超时：50 ms；
- 链路和设备恢复：连续3帧；
- 空闲时默认只要求 K230_1；任务期间由 `motion_coordinator` 按子流程动态设置必需设备；
- 设备可用条件：链路在线、`VALID=1`、`STALE=0`且数值合理；
- `VALID=0`时数值字段不得使用；
- `VALID=1`时数值0是合法数据；
- UART/DMA错误后先在回调中重启，失败后由 LegacyIoTask 继续重试；
- 超时和设备可用性由C552模块持续发布；后续PID/运动控制模块必须据此执行模式相关停机；
- 通信恢复不会自动续跑故障前的运动。

Shell输入大写命令 `C552`，USART1将输出：

- 链路 ONLINE、RECOVERING 或 TIMEOUT；
- 总警示和运动许可；
- 序列号、STATUS和帧龄；
- TOF1/2/3、K230_1/2 的 VALID、STALE、READY和解析值；
- 版本、长度、ID、CRC、序列号、UART和DMA错误计数。

中断和DMA回调中禁止使用 `printf`、阻塞等待、浮点计算或运动控制。

当前真实CAN配置是：

- FDCAN2；
- PB12=RX、PB13=TX，AF9；
- 120 MHz内核时钟；
- 125 kbit/s；
- Classic CAN；
- 29位扩展ID，默认`0x1000`；
- RX FIFO0和TX FIFO各4个8字节元素；
- LegacyIoTask 使用5 ms空闲时间判断一条上层长消息结束。

`FDCAN1-debug-summary.md`描述的是历史调试阶段，不代表当前源码。新对话不得仅依据文件名
或该文档把当前外设改成FDCAN1。

## 10. 重要约束和已知风险

1. 不要直接重新生成CubeMX代码。先比较`TestH743.ioc`和当前源码，尤其是FDCAN、USART6、DMA和中断。
2. 当前CAN是FDCAN2 PB12/PB13，不是历史文档中的FDCAN1 PA11/PA12。
3. USART6已由`main.c`初始化为Z轴控制链路，占用PC6/PC7；PA11/PA12不再由Z轴链路占用。
4. Ethernet当前禁用。没有RMII 50 MHz参考时钟时调用完整HAL ETH初始化会进入Error_Handler。
5. USART3由C552 DMA独占，不允许再用阻塞式TOF收发。
6. DMA1/2不能访问DTCM `0x20000000`。C552 DMA缓冲区当前位于AXI SRAM。
7. 当前未启用D-Cache；以后启用时必须处理DMA Cache一致性或划分非缓存区。
8. IWDG约2秒超时。长时间阻塞、调试断点或新增阻塞等待可能导致复位。
9. `axis/servo/stepper/buzzer/key/wdg/tof` 只存在于旧工程或历史文档，不能作为当前运行路径。
10. 自动任务必须通过 `motion_coordinator` 取得所有权，不得绕过它直接并发运动。
11. `wdg.c`与`iwdg.c`是两套IWDG封装，只能选择一套初始化。
12. C552 必需设备掩码按当前 owner/子流程动态切换；不要恢复成固定 TOF1+TOF2 掩码。
13. `printf`走USART1轮询发送，长日志会阻塞调用它的任务；中断中绝对不能打印。
14. Git 工作区可能已有实机调试改动；修改前后执行 `git status --short`，不要覆盖无关改动。
